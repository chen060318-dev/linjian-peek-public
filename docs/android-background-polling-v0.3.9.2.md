# v0.3.9.2 Android 后台命令轮询恢复

## 修复的问题

v0.3.9.1 已经补齐命令 TTL、回执、去重和截图关联，但 HyperOS 等系统可能挂起前台服务的轮询线程，同时进程内 `running=true` 仍未清除。旧的无障碍兜底轮询只看该布尔值，会误判前台轮询健康，导致 App 切到后台后命令再次停在 `dispatch_attempts=0`。

## 新机制

- 前台轮询每轮更新单调时钟心跳；UI 和无障碍兜底以心跳新鲜度判断服务是否真正工作。
- 心跳过期后，无障碍服务在约 6 秒粒度接管命令轮询，不再依赖陈旧的 `running` 标记。
- 前台服务持有 `PARTIAL_WAKE_LOCK`，避免熄屏或切换 App 后 CPU 挂起轮询。
- 任务被划走、服务被系统销毁、设备重启或 APK 覆盖安装后，在用户未主动停止服务的前提下自动恢复。
- 用户主动点击“停止服务”仍会写入 `user_stopped=true`，不会被自动拉起。

## 验收

1. 启动掌心窗服务后切到小红书并保持掌心窗在后台。
2. 远程调用 `get_screen_break_state`，应在 20 秒内出现 `dispatch_attempts >= 1` 且最终 `completed`。
3. 远程调用 `screen_break_app`，应及时出现拦截页，并按手机实际执行时间计时。
4. 锁定到期后再次查询，状态应为 `active=false`。

部分 HyperOS 设备仍可能要求用户在系统设置中允许“自启动”并将电池策略改为“不限制”；代码无法绕过系统明确关闭的后台权限。
